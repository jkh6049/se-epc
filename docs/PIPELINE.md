# EPC사업부 파이프라인 — 개발 방향 기준

이 문서는 대시보드를 사업관리팀 도구에서 EPC사업부 전체 파이프라인 도구로 넓혀 가기 위한 기준이다.
새 기능을 만들거나 기존 코드를 고칠 때 이 문서와 코드의 기준 블록(`legacy/index.html` 의 `v48: EPC사업부 파이프라인 기준`)을 따른다.

## 1. 조직과 범위

| 팀 | 코드 | 범위 |
|---|---|---|
| 영업팀 (모듈영업 포함) | `sales` | 사업 발굴 · 입찰 · 계약 |
| 사업지원팀 | `support` | 제안서·입찰 서류, 설계·인허가, 용역사·실행예산 확정 — **착공 전까지** |
| 사업관리팀 | `pm` | **착공 이후** 시공 · 기성 · 준공 · 인수인계 |
| O&M | `om` | 준공 이후 운영·점검·AS |

- 인계 시점 = **착공계 승인 완료** (단계 `plan` → `start`). 사업지원팀이 용역사(하도급 계약)와 실행예산을 확정하고 착공계 승인까지 받은 상태로 사업관리팀에 넘긴다.
- 인수인계 자료(03 §1)에는 착공계·실행예산·하도급 선정이 "영업팀 → 사업관리팀 인계 시점" 업무로 적혀 있다. 현재 회사 합의(착공 전까지 사업지원)를 우선 적용하고, 경계가 바뀌면 `PIPE48` 과 템플릿만 고친다.
- 영업팀과 사업지원팀은 민간·공공을 모두 다룬다. 경계가 단계로 딱 나뉘지 않으므로 단계마다 주관 팀과 지원 팀을 함께 둔다.

## 2. 단계 (현장 1건이 처음부터 끝까지 같은 레코드)

| 키 | 단계 | 주관 | 지원 | 비고 |
|---|---|---|---|---|
| `lead` | 발굴·검토 | 영업 | | 아직 화면 없음 (future) |
| `bid` | 입찰·제안 | 영업 | 사업지원 | 제안서·입찰 서류는 사업지원 작성 (future) |
| `contract` | 계약 | 영업 | 사업지원 | |
| `design` | 설계 | 사업지원 | | |
| `permit` | 인허가 | 사업지원 | | 현장마다 필요한 인허가가 다름 |
| `plan` | 착공 준비 | 사업지원 | | 공사계획신고 수리 · 하도급 계약 체결 · 착공계 승인 |
| `start` | 착공 | **사업관리** | | **인계 시점** |
| `procure` | 조달 | 사업관리 | | |
| `build` | 시공 | 사업관리 | | |
| `inspect` | 사용전검사·COD | 사업관리 | | |
| `handover` | 준공·인수인계 | 사업관리 | | |
| `om` | O&M | O&M | | |

- 수주 결과: 수주 / 실주 / 입찰 포기 / 보류. 실주·포기·보류는 기존 '종료 처리'(종료 현장 보관)에 사유로 합류시켜 기록을 남긴다. 투찰가·낙찰사·사유를 함께 기록한다.
- 현장은 영업 단계부터 O&M까지 **하나의 레코드**로 이어간다. 진행사항·서류·마일스톤 이력이 팀이 바뀌어도 끊기지 않게 하기 위함이다. 별도 '영업 건' 레코드를 따로 만들지 않는다.

## 3. 인계 원칙

- [사업관리 인계] = 현장 단계를 `start`(착공)로 넘기는 동작. 지금은 현장 상세의 단계 변경·칸반 이동이 이 역할을 한다 (사업지원 메뉴를 열 때 전용 버튼 추가).
- 인계하면 `p.handoff.pmAt`(인계일), `pmBy`, `pmGaps`(당시 미비 사항)를 기록한다.
- 체크리스트로 **막지 않는다** (현장마다 조건이 다르므로). 빠진 것만 경고로 보여준다 — `handoverGaps48(p)`:
  - 용역사(하도급사) 미등록
  - 실행예산 미확정
  - 착공 전 단계 마일스톤 미완료
- 인계하면 사업관리 기본 마일스톤을 깔고, 이후에는 지금처럼 현장별로 직접 수정한다.

## 4. 마일스톤

- 템플릿 데이터 형식은 그대로 두고, 항목의 `stage` 로 담당 팀을 계산한다 — `tplTeam48(item)`.
- 기본 템플릿은 두 벌로 나눈다: 사업지원용(계약~착공 준비) · 사업관리용(착공~준공). 현장별로 자유롭게 고친다.
- 인허가는 기본 목록을 깔고, 현장마다 필요 없는 항목은 '해당없음'으로 뺀다 (발전사업허가 사전 취득, 자가소비라 불필요 등).
- 2026-11-17 반영 (v49, 서버 데이터를 받은 직후 1회 자동 맞춤 — `legacy/live.js` 의 `onLiveSnap` 훅):
  - '착공계 승인'·'하도급 계약 체결' → 착공 준비(`plan`, 사업지원) 단계로 이동 (템플릿 + 기존 마일스톤)
  - '계약 체결 / 킥오프' = 영업, '실행예산 승인' = 사업지원 (템플릿 항목별 `team` 지정)
  - 사업관리 추가: 착공 (현장 개시) · 인계 킥오프, 기준 공정표 · 3주 롤링 셋팅 [03 §1-대내①③], As-Built 도면 · O&M 매뉴얼 제출, 하자보증이행증권 제출 [03 §5-대외③④]
  - 파트너·사이트 템플릿은 구성이 달라 항목 추가 없음
- 마이그레이션처럼 데이터를 고치는 코드는 반드시 `onLiveSnap` 이후에 돌린다. 서버 데이터를 받기 전 로컬 데이터는 오래됐을 수 있다.

## 4-1. 사이트 선정 상태 (복수 사이트 현장)

- 사이트마다 선정 상태: 확정(기본) / 선정 대기 / 제외 + 결정 예정일 + 메모. 사이트 편집 창에서 지정.
- 선정 대기·제외 사이트의 마일스톤은 지연·진척(마일스톤 완료율)·다음 일정 집계에서 빠진다. 기록은 그대로 둔다.
- 홈 '이번 주 확인할 것'에 선정 대기 사이트가 표시되고, 결정 예정일이 지나면 빨간색.
- 선정되면 '확정'으로 바꾸고 일정만 다시 잡는다. 탈락하면 '제외' (사이트 기록은 남김).
- 예: 세종 및 전사 유휴부지(서부발전) 군산발전본부 — 선정 여부 미정 (`data/patch/2611-gunsan-sel.json`)
- 계약금액·용량·예상공정표(매출 배분)는 건드리지 않는다. 제외가 확정되어 계약이 바뀌면 그때 금액·공정표를 고친다.

## 5. 지표 정의 (모든 화면 공통)

2026-11-17 건호 확정: **원가투입법 하나로 통일.** 물리적 공정률(수기 실제공정률)은 쓰지 않는다 (주간보고 PPTX 2쪽의 '물리적 공사 진행률' 정의보다 우선).

| 지표 | 정의 | 함수 |
|---|---|---|
| 공정률 | 누적원가 ÷ 실행예산. 누적원가 = ERP 결산 누계, 마감 전 달은 원가 전표(외주용역비·경비·기자재 등 전부) 누계 | 실적관리 `cpct55(c)` · 대시보드 `cpct55(p)` / `physPct47(p)` / `cost55E(e)` |
| 진행매출 (매출) | 공정률 × 계약금액. 구분손익(재무)을 올린 달은 재무 숫자 | `calcProject`, `actYear41`, `poc55(R)` |
| 주간보고 실적관리(8p)·월간 누적 실적 매출 | 진행매출. 범위 = 진행매출 표 [프로젝트 선택], 기타 계정 포함 여부 = [기타] (브라우저별 기억) | `poc55(R)`, 부모 `RS55_ETC` |
| 매출이익 (월간 누적) | 진행매출 − 매출원가 | `poc55` |
| 전년이월 | 올해 1월 1일 전에 계약한 현장(계약일 없으면 전년까지 진행매출이 있는 현장)의 계약금액 · 전년까지 누계 · 전년 말 잔액. 해가 바뀌면 자동으로 직전 연도 기준 (2026년: 루프5차 iM에셋) | `R.carry` |
| 당해연도 누적 / 프로젝트 총누적 | 1~12월 합계 / 전년이월 + 당해연도 누적. 미수금·계약잔액은 잔액이라 기준일 값 | `R.tot` / `R.all` |
| 계약잔액 | 계약금액 − 누적 진행매출 (전년 이월 포함, 기타 계정 제외) | `poc55` |
| 세금계산서 매출 (참고) | 기성 확정 후 발행한 계산서 누계 (선급금 제외 · VAT 별도). 수금·미수금은 계산서 기준 | `sales45` → `c.inv` |
| 기성률 | 기성 회차에 입력하는 발주처 청구 기준 진척 %. 공정(SPI)·EVM 계산용, 공정률과 별개 | `kpiOf(p).pct` |
| 경영보고 누적 매출액 | 세금계산서 기준 유지 (변경 요청 없음) | `buildReport` `kpi.salesCum` |
| 마일스톤 | 완료 마일스톤 수 ÷ 전체 (해당없음 제외). 일정 관리용, 공정률과 다름 | `progress(p)` |
| 원가 집행률 | 지급 전표 ÷ 실행예산. 전표 없는 현장은 결산 누적원가 ÷ 실행예산 | `pfRow().costRate` |
| 수행 중 현장 (홈) | 종료 처리 안 된 대시보드 현장 | `activeProjects()` |
| 진행 현장 건수 (주간보고) | 실적관리 현장 중 '진행 현장 건수에 포함' 체크 현장 (준공 포함) | 주간보고 `kpi.n` |

## 6. 확장 순서

1. **사업관리 안정화** (현재) — 착공 이후 현장 관리, 기성·실적, 주간보고
2. **사업지원 확장** — 사업지원 메뉴(착공 전 현장 · 인허가 · Task · 진행사항), 인허가 탭을 사업지원으로 이동, 인계 버튼
3. **영업 확장** — 발굴·입찰 단계(`lead`, `bid`) 화면, 수주/실주 기록, 수주율·수주액 집계
4. **경영 요약** — 파이프라인 수주 지표 + 실적 지표를 PDF·엑셀 한 장으로 (팀장·전무 보고는 PDF·엑셀 기준)
   - 2026-11-17: '사업부 파이프라인 요약' 신규 출력물 (보고서·엑셀 목록, `pp50Pdf` A4 가로 1장 · `pp50Xlsx` 4시트: 요약/팀별 현황/현장별/확인 필요). 영업 화면이 생기면 발굴·입찰 단계 집계·수주율을 여기에 추가
   - **기존 회사 양식(경영보고·주간보고·실적현황·경영계획 등)은 구조를 바꾸지 않는다.** 새 지표·화면은 별도 이름의 새 출력물로 만든다.

메뉴 목표 (2~3단계에서 적용):
- 공통: 홈 · 전체 파이프라인(발굴~O&M 단계별 보드) · 일정 · 협력사 · 사내 양식
- 영업: 발굴·입찰 현장 · Task · 진행사항
- 사업지원: 착공 전 현장 · 인허가 · Task · 진행사항
- 사업관리: 착공 후 현장 · 기성 청구 · 공정표 · Task · 진행사항 · O&M

## 7. 코드 규칙

- 단계·팀·인계 기준은 `PIPE48` / `TEAM48` 한 곳에서만 정의한다. 새 코드는 `stageTeam48`, `teamOf48`, `isPmScope48`, `isPreStart48`, `handoverGaps48` 를 쓴다.
- 단계 키 목록(`["contract","design",...]`)을 새로 하드코딩하지 않는다.
- 기존 하드코딩 (확장 단계에서 위 함수로 교체):
  - `stage==="om"` / `stage!=="om"` 약 40곳 — O&M 여부 판단
  - `["contract","design","permit","plan"]` — 협력사 '설계·인허가 단계' 집계
  - `["start","procure","build","inspect","handover"]` — 협력사 '시공 중' 집계
  - `["contract","design"]` — 영업 인계 체크리스트 경고 대상
- 지표는 5장 정의와 함수만 쓴다. 화면에서 새로 계산식을 만들지 않는다.
- 화면에 보이는 단계 목록(`STAGES`)은 아직 계약~O&M. `lead`·`bid` 는 영업 화면을 열 때 합류시킨다.
